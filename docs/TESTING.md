# 测试建议

## 推荐顺序

| 用例 | 检查内容 |
| --- | --- |
| PT005–009 | 正方形、横竖照片、宽屏及手机单屏基准，检查原始比例、适应窗口与铺满裁切 |
| PT001–004、010–012 | 竖向长图、横向全景；核对分段连续、首尾可达、文字细节与缩放 |
| PT001、013、014 | 相同 9:200 比例、不同分辨率，区分源图清晰度与解码缩放问题 |
| PT015 | 奇数宽高尺寸，观察取整、缺边及缩放位置 |
| PT016–018 | 512×8191 / 8192 / 8193，隔离最长边 8192 附近的行为 |
| PT022–024 | 2000×3999 / 4000 / 4001，隔离总像素 800 万附近的行为 |
| PT019 | 透明、半透明及不透明区域，在浅色和深色背景下检查合成与边缘 |
| PT020–021 | 编码前像素相同的 JPEG / PNG，区分有损压缩与加载算法差异 |

8192 和 800 万只是本套用例选取的测试点，不代表 Android、iOS、浏览器或所有设备的通用限制。两组边界互相隔离，避免同时跨越两个条件。

PT014 含 103,680,000 像素，按 RGBA8 整图展开约 396 MiB；这只是未压缩像素大小，不能据此推断应用实际内存消耗。建议最后单独测试，再观察应用是否按显示范围和尺寸加载。

## 每张图片的检查项

- **加载**：能够显示，失败时有明确状态，不出现崩溃或无限占位。
- **比例和边缘**：完整显示模式下可看到内容首尾；铺满模式的裁切应符合预期，不异常拉伸。横向全景需检查左右端点。
- **细节**：放大文字、条纹和棋盘格，比较清晰度是否改善。缩略图中的细线变灰或出现摩尔纹可能是正常采样现象，应在相应缩放级别复核。
- **交互**：滚动、翻页、缩放和切换图片时无异常跳位或错误缓存复用。记录设备、模式和用例编号，以便复现。
- **透明度**：浅色与深色背景均检查；预览的棋盘背景仅用于展示，不是透明原图的一部分。

## 自动验证的范围

`python3 scripts/verify.py` 使用 Python 标准库检查：

- 图片集合、编号、名称、尺寸、最简比例、格式、文件大小和 SHA-256；
- PNG 块 CRC、JPEG 帧头及结束标记；
- PT019 的实际 alpha 通道含全透明、半透明和不透明像素；
- PT020 / PT021 的编码前像素哈希记录相同、输出格式不同；
- 上游字体及其许可证保持固定版本字节，授权文件齐全。

格式对照的源像素哈希由生成器计算并写入 `manifest.json`；验证现有文件时检查这份记录，重新生成时再次计算并比对。PNG/JPEG 的最终编码文件不应具有相同哈希。

自动验证不等于完整解码所有文件或视觉验收。它不测设备帧率、解码速度、内存峰值、HDR、广色域、EXIF 方向或动画格式。这些需要专门用例和目标环境中的测量。
